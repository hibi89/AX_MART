# AXMART PC CARE v0.1-alpha — Windows PC·USB 포터블 진단·복구 보조 도구

**상태: 초기 시험용, 판매 불가. 실제 Windows PC에서 실행 검증 전.**

## 기본 실행 (Release A 개발용 시작 메뉴)

정상 부팅 Windows 11에서 `START_PC_CARE.cmd`를 더블클릭하면 비관리자 오프라인 텍스트 메뉴가 나타난다. **1 읽기 전용 진단 / 2 읽기 전용 자가검사 / 3 로컬 보고서 위치 / 4 복구 안전 안내 / 5 오프라인 검사 이력 비교 / 0 종료** 기능만 있다. 메뉴는 수리 실행기 또는 WinRE를 자동으로 시작하지 않는다. 실패 시 실행기 오류를 표시하고 파일을 삭제하거나 인터넷으로 보내지 않는다.

기존 `RUN_HEALTH_CHECK.cmd`와 `RUN_SELF_TEST.cmd`를 직접 실행하는 방식도 계속 지원한다. 전체 패키지는 실기기 검증 전 내부 시험 전용이며 무료/유료 배포 불가.

## 구성

| 파일 | 실행 위치 | 기능 | 시스템 수정 |
|---|---|---|---|
| `START_PC_CARE.cmd` | 정상 부팅 Windows | 진단·자가검사·보고서 위치·안전 안내 통합 메뉴(수리 자동 실행 없음) | 없음 |
| `RUN_HEALTH_CHECK.cmd` | 정상 부팅한 Windows 10/11 | OS·저장장치 여유 공간·일부 저장장치 상태·최근 30일 BugCheck(1001)·예기치 않은 종료(41/6008)·스토리지 이벤트 점검, HTML/JSON 보고서 | 없음 (보고서 파일만 생성) |
| `RUN_SAFE_REPAIR.cmd` | 정상 부팅한 Windows, 관리자 실행 | 백업/승인 확인 후 DISM RestoreHealth + SFC Scannow | **있음** |
| `recovery/WINRE_READ_ONLY.cmd` | Windows RE 명령 프롬프트 | 설치 Windows 후보·BitLocker 보호 상태·부트 항목 확인, 로컬 텍스트 로그 | 없음 (보고서 파일만 생성) |

## 사용

1. USB 또는 일반 폴더에 이 전체 폴더를 **압축 해제**한다. 원래 폴더 구조를 유지한다.
2. Windows가 시작되면 `RUN_HEALTH_CHECK.cmd`를 더블클릭한다. 완료 후 `REPORTS`의 `.html`을 연다. 관리자 권한이 없으면 일부 데이터가 누락될 수 있다.
3. 보고서에 이상이 나왔다고 바로 수리하지 않는다. 중요 파일은 먼저 별도 드라이브에 백업한다.
4. Microsoft 시스템 파일 복구가 필요하다고 판단될 때만, 백업한 후 `RUN_SAFE_REPAIR.cmd`를 **관리자 권한으로 실행**한다. 확인 문구를 직접 입력해야 수리한다.
5. Windows가 부팅되지 않으면 [Microsoft 정식 Windows 복구 미디어](https://support.microsoft.com/windows/create-installation-media-for-windows)로 Windows RE에 진입한다. 명령 프롬프트에서 USB 드라이브 문자를 확인하고 `E:\AXMART_PC_CARE_USB_v0.1\recovery\WINRE_READ_ONLY.cmd`처럼 실행한다. (예시 E:는 실제 USB 문자로 바꾼다.)

> **중요:** 이 ZIP 자체는 부팅용 USB 이미지가 아니다. Microsoft의 Windows 설치/복구 USB를 별도 준비해야 한다. 자체 WinPE 이미지의 번들·상용 재배포는 별도 권리 확인 대상이다.

## 개인 정보

서버 없음, 계정 없음, 외부 AI API 없음, 자동 업로드 없음. 사용자 이름·디스크 시리얼·이벤트 원문은 진단 JSON에 의도적으로 저장하지 않는다. 복구 모드의 `bcdedit` 출력은 환경 식별 정보를 포함할 수 있으므로 **REPORTS 공유 전 검토**한다.

## 한계

- '특이사항 없음'은 모든 부품의 정상·무고장 보증이 아니다. BugCheck 정보는 이벤트 로그가 삭제되었거나 접근 권한이 없으면 확인할 수 없다.
- BSOD가 계속되면 하드웨어, 온도, 드라이버, SSD, RAM 등의 추가 테스트가 필요하다.
- EFI/BCD 수정, 파일시스템 쓰기 복구, 파티션 수정, Windows 초기화는 자동화하지 않는다.
- 정식 판매용 기능·품질/지원 약관·Win10/Win11 실기기 검증·코드 서명은 미완료.

## 인쇄용 수리 상담 요약 (P2 초기 구현, 검증 전)

진단 HTML에는 'PC 점검 · 수리 상담 요약'이 추가된다. 브라우저의 **Ctrl+P → PDF로 저장** 기능으로 상담표만 출력하도록 CSS를 구성했다. 추가 PDF 엔진, 서버, 외부 폰트는 필요하지 않다.

- 상담표에는 최근 주요 이벤트 기록 4건(이벤트 ID와 UTC 기록 시각), 검토할 증거 종류, Windows 빌드, 저장장치 상태 신호, 보수적 백업 권고, 수리점 질문 3개를 싣는다.
- 원본 이벤트 메시지·시리얼번호·장치명·사용자 계정·경로는 상담표에서 제외한다. 상세 JSON/HTML은 여전히 더 많은 데이터가 포함될 수 있어 공유 전 사용자가 검토해야 한다.
- 사용자의 증상은 출력 후 종이에 직접 메모한다. 자동으로 증상 내용을 기록하거나 전송하지 않는다.
- 출력이 실제 A4 한 장인지, Windows 기본 브라우저와 한글 폰트에서 정상 동작하는지는 **미검증**이다. QR 코드는 아직 개발/검증하지 않았다.

## QR 공유 기능: 명시적 오프라인 이미지 생성 (P2 구현, 실제 스캔 미검증)

- 보고서의 **오프라인 공유 텍스트 (QR용)** 영역은 사용자가 직접 펼쳐 내용을 확인하는 방식이다. 자동 복사·전송·네트워크 호출 없음.
- 고장/수집 신호는 정해진 범주만 사용하고, 최신 기록의 UTC 기록 시각은 검증된 형식에서만 선택. 개인정보 원문·디스크 시리얼·사용자 이름·전체 경로는 공유 텍스트에서 제외.
- 텍스트 본문은 최대 **250 UTF-8 바이트**이고 초과하면 출력하지 않는다. 카테고리가 더 많아 2개만 표기할 경우 '외 N종'으로 생략 사실을 명시한다.
- 미리보기의 **전체 선택** 버튼은 텍스트 선택만 수행하며, **Ctrl+C**와 제3자 공유는 사용자가 직접 결정한다. 별도의 **오프라인 QR 이미지 만들기** 버튼을 누르면 HTML에 포함된 로컬 라이브러리로 이미지를 생성한다. 자동 생성·서버 전송·QR URL 업로드는 없다. 누구든 QR 사진이나 텍스트 복사본을 받으면 내용을 읽을 수 있다.
- 메타데이터만 로컬 JSON의 sharePreview에 기록하며 실제 공유 문자열은 JSON에 별도로 저장하지 않는다. HTML 내부에는 펼치기 전에도 미리보기 텍스트가 포함될 수 있으므로, **전체 HTML 공유 시 별도 검토**가 필요하다.
- QR bitmap 인코더는 **davidshimjs/qrcodejs(MIT)** 를 로컬에 동봉하며 `ui/QR_CODE_LICENSE.txt`에 저작권/라이선스 원문을 보존한다. 생성용 JS는 진단 HTML에 인라인으로 포함되어 원본 USB 없이도 로컬 HTML에서 동작하도록 설계했다. 라이브러리가 없으면 텍스트 전용으로 복귀한다.
- **Windows 브라우저 실동작·스마트폰 카메라 스캔·한글 UTF-8·인쇄/흰 여백 검증은 미실행.** QR 생성 기능이 구현됐더라도 베타 출시 가능 또는 스캔 성공을 주장하지 않는다.

## Windows 초보자용 안전 시험 (공개 전 내부 전용)
압축 해제한 USB 폴더에서 `RUN_SELF_TEST.cmd`를 더블클릭한다. PowerShell 문법 검사 후 **최근 1일에 대한 읽기 전용 검사**와 로컬 HTML/JSON 생성 여부만 검증한다. 시스템 파일 수리는 실행하지 않는다. 완료 화면의 PASS/FAILED와 종료 코드를 확인한다. 시험 중인 Windows 10/11에서만 사용하며, 개인정보가 포함될 수 있는 보고서를 그대로 외부에 공유하지 않는다. 결과가 PASS여도 WinRE·복구 기능 안전성은 별도 검증이 필요하다.

### QR 안전성 보강 (2026-10-30)

- QR용 텍스트는 허용된 한국어 상태·장애 분류·UTC 기록 시각·인과관계 경고·백업 권고로 구성한 **7줄 고정 형식**만 인코딩한다. 추가 문구, 사용자/장치 이름, 경고가 제거된 임의 텍스트를 QR로 변환하지 않는다.
- 사용자가 공유 텍스트를 변경하거나 QR 재생성을 실패하면 기존 QR 이미지를 제거한다. 이전 QR을 새 내용으로 착각하지 않도록 처리했다.
- 검증: GitHub와 동일한 QR UI JavaScript를 Chromium 가상 HTML/가짜 QR 생성자로 실행한 사용자 클릭·입력 변경·250바이트·보안 필드 검사 **13/13 조건 통과**. 공급된 실제 `ui/qrcode.min.js`를 사용한 이미지 디코딩·스마트폰 스캔 테스트가 아니므로 공개 QR 기능의 종합 QA는 아직 미검증.
- 선택형 독립 스캐너 검사기: `python tests/qr_browser_smoke.py --chromium /path/to/chromium` (개발 환경용 `playwright`·`opencv-python` 필요, 고객용 ZIP에는 동봉하지 않음). 라이브러리 QR 실제 생성→픽셀 디코딩→UTF-8 정확 일치·개인정보 미전송·기존 이미지 무효화를 요구한다.
  
### QR 기록시각 무결성 (2026-10-30)

QR 이미지 생성 전 UTC 기록 시각을 **정규식 + 실제 달력 날짜**로 이중 검증한다. 2026-02-29/2026-02-30처럼 존재하지 않는 날짜는 차단하고, 2024-02-29처럼 정상 윤일은 허용한다. 사건 발생 시각이 아니라 시스템의 **이벤트 기록 시각**임을 표시하고, 조회 불가는 `미확인`으로 남긴다.

동일한 GitHub JS 소스(커밋 blob 기준)로 Linux headless Chromium + 가짜 QR 생성자를 이용한 기존 13건과 날짜 추가 7건을 **20/20 통과**했다. 실제 `qrcode.min.js`가 만들어 낸 QR 픽셀/디코더·스마트폰 앱, Windows PowerShell 및 A4 인쇄는 미검증. `tests/qr_browser_smoke.py`에 실제 QR 렌더+OpenCV 디코딩 및 달력 경계 테스트를 등록했으나 해당 전체 스캐너 테스트는 아직 실행하지 않았다.

### QR 스캔 호환성 주의 (개발 중)

현재 동봉한 QR 라이브러리는 한글 텍스트에 UTF-8 BOM을 포함할 수 있다. 일부 QR 디코더에서는 복원된 텍스트 앞에 보이지 않는 U+FEFF 문자가 남는다. 제품의 QR 미리보기·UTF-8 디코딩 검사에는 이 차이를 명시적으로 보고하도록 테스트를 보강했다. 실제 동봉 라이브러리 및 휴대전화 스캔에서 문제가 없는지 아직 검증하지 않았다. 따라서 **QR 기능의 상용/공개 배포는 계속 보류**한다.


### 한글 QR 라이브러리 용량 오류 수정 (2026-10-30)

기존 동봉된 qrcodejs가 한글 다음 영문·숫자를 처리할 때 이전 UTF-8 바이트를 잘못 재사용해, **195바이트 정상 상담 문구마저 QR 생성 실패**하는 버그를 발견했다. MIT 저작권을 유지한 채 라이브러리 인코딩 루프에서 문자별 바이트 버퍼를 초기화하도록 최소 수정했다. 수정 전 용량 초과 오류를 재현하고, 수정된 실제 QR 인코더의 혼합 문자 6종 데이터를 검증했다.

실제 인코더가 계산한 57×57 QR 모듈을 OpenCV 디코더로 읽어 한글 원문을 복원했다. 단, 라이브러리는 한글 앞에 UTF-8 BOM(`U+FEFF`)을 삽입하므로 디코딩 결과에도 이 문자가 표시될 수 있다. **Windows 브라우저의 실제 렌더링·휴대전화 카메라 스캔·USB/복구 환경은 아직 미검증**이다. 이를 통과하기 전 일반 배포·유료 판매는 보류한다.


### QR 오프라인 회귀 시험 확대 (2026-10-30)
